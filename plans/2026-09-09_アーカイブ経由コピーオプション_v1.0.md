# 計画書: アーカイブ経由コピーオプション(v1.0)

## 目的

大量の小さいファイルをコピーする際に、Quick7Zipの圧縮ロジックを流用して「1個のアーカイブにまとめてから転送」するオプションを追加する。既存のCopyEngine(ファイル単位で複数ワーカーが並列コピーする方式)に対する代替経路として実装する。

## 現状分析

### QuickFileCopyの現状のコピー方式
- `core/native/src/copy_engine.cpp` の `CopySession::run()` は、スキャナースレッド1本がディレクトリを走査してファイル単位の `CopyJob` をキューに積み、複数ワーカースレッドが1件ずつ `CopyFileExW` を呼んでコピーする(1ファイル=1API呼び出し)。バッチ化・アーカイブ化は一切していない。
- ワーカー数は宛先種別で自動調整される(`automatic_worker_count`, [copy_engine.cpp:1401-1425](../core/native/src/copy_engine.cpp#L1401-L1425)): UNC=8固定、クラウド同期フォルダ=12固定、通常ローカル=論理コア数×2(4〜16)。
- `CopyOptions`([copy_engine.h:22-41](../core/native/include/qfc/copy_engine.h#L22-L41))には hard link・reparse point・EFS暗号化・ACL/SACL・sparse file・圧縮属性を個別に保存するフラグ群があり、これらは実際に実装済みで機能している。

### Quick7Zip側の圧縮ロジック(流用元)
`C:\Users\0120025-Z100\source\project\Quick7Zip\core\native\engine.cpp` を確認した。重要な事実:
- Quick7Zipは圧縮ライブラリを内蔵していない。**レジストリ(`SOFTWARE\7-Zip`)またはPATHから、ユーザー環境にインストール済みの `7z.exe` を探して(`FindSevenZip`, [engine.cpp:195-213](file:///C:/Users/0120025-Z100/source/project/Quick7Zip/core/native/engine.cpp#L195-L213))、`CreateProcessW` で外部プロセスとして起動するラッパー**である。7-Zip未インストール環境では動作しない。
- ファイル群を事前スキャンして件数・平均サイズ・既圧縮率などを見て、圧縮レベル・スレッド数・ソリッドモードを自動選択する(`ChoosePlan`, [engine.cpp:307-329](file:///C:/Users/0120025-Z100/source/project/Quick7Zip/core/native/engine.cpp#L307-L329))。
- `RunArchive`([engine.cpp:635-](file:///C:/Users/0120025-Z100/source/project/Quick7Zip/core/native/engine.cpp#L635))は `7z a -t7z ...` を組み立てて実行し、パイプで進捗を読み取り、キャンセル時は `TerminateProcess` する([engine.cpp:560-631](file:///C:/Users/0120025-Z100/source/project/Quick7Zip/core/native/engine.cpp#L560-L631))。
- **重要**: Quick7Zipには「展開(extract)」ロジックが存在しない。圧縮(アーカイブ作成)専用アプリであり、`7z x` に相当するコードは無い。今回「コピー先で展開」を実現するには、展開部分は新規実装が必要。
- QuickFileCopyとQuick7Zipは別リポジトリ・別ビルド定義(CMakeLists.txt)で、共有ライブラリとしてリンクする仕組みは無い。よって「流用」は、`FindSevenZip`/`7z a`引数組み立て/`CreateProcessW`実行パターンを**QuickFileCopy側に移植(コードとして書き写す)**する形になる。

### 前提を崩す技術的な制約(重要・正直に書く)

「ZIP化して転送→展開すれば速くなる」という前提は、**宛先がネットワーク共有(UNC/SMB)の場合は成立しない可能性が高い**。理由:

- QuickFileCopyは単一プロセス・単一マシンで動作する。展開(`7z x`)を実行するのも同じ端末であり、展開時の書き込み先がUNCパスなら、結局そこで小ファイルN個分のSMB書き込み(オープン/クローズの往復)が発生する。これは現状の並列コピーと本質的に同じコストであり、そこにアーカイブ作成・アーカイブ転送・展開のオーバーヘッドが**上乗せされるだけ**になる。
- 本当に「1個の転送で済ませる」効果が出るのは、**展開を宛先側の別マシン/別セッションが行う場合**(遠隔地への手動zip転送のような使い方)、または**アーカイブのまま展開せずに置く場合**に限られる。
- 一方、クラウド同期フォルダ(OneDrive等)や、ディレクトリエントリ数がボトルネックになる低速ローカルメディア(USB接続の外付けHDD等)では、アーカイブ化によって書き込みが「大きい1ファイルの逐次書き込み」に置き換わる分、一定の改善が見込める可能性はあるが、実測未検証。

このため、本計画では**2つのサブモード**に分けて実装し、UI上でも効果の性質が異なることを明示する。

## 変更内容

### 追加する機能

`CopyOptions` に以下を追加(`core/native/include/qfc/copy_engine.h`):

```cpp
enum class ArchiveTransferMode {
    off,                 // 既定。現行のファイル単位コピー
    archive_only,        // アーカイブ化して転送、宛先には .7z のまま置く(展開しない)
    archive_and_extract,  // アーカイブ化して転送し、宛先で展開する
};
// CopyOptions に追加
ArchiveTransferMode archive_transfer_mode = ArchiveTransferMode::off;
```

### 新規ファイル: `core/native/src/archive_relay.cpp` / `include/qfc/archive_relay.h`

Quick7Zipの `FindSevenZip` / `CreateProcessW`実行パターンを移植し、以下を実装する:
- `FindSevenZip()`: レジストリ + PATH + Program Files から `7z.exe` を検出(Quick7Zipと同一ロジックを移植)。
- `CreateArchive(...)`: スキャナーが収集した `CopyJob` のソースパス一覧をファイルリスト化(`-i@filelist.txt`)し、ローカルの一時ディレクトリ(`%TEMP%`、宛先ではなく必ずローカル)に `.7z` を作成する。圧縮レベルは既定で `-mx=1`(高速)、ソリッドモード `-ms=on`。目的が「件数を減らす」ことであり「サイズを減らす」ことではないため、強圧縮はデフォルトにしない。
- `ExtractArchive(...)`: `7z x -y -o<destination>` を宛先に対して実行する新規ロジック(Quick7Zipには無いため新規実装)。
- キャンセル・進捗パイプ読み取りはQuick7Zipの `RunArchive` と同じ `CreateProcessW` + パイプ + `TerminateProcess` パターンを踏襲する。

### `copy_engine.cpp` の変更

- `CopySession::run()` の先頭で `options.archive_transfer_mode != off` の場合は専用の実行パスに分岐する。
- **必須の安全ガード**: `archive_transfer_mode != off` かつ以下のいずれかが有効な場合は**即座にエラーを返し実行しない**(アーカイブ経由では属性を保持できないため):
  - `preserve_hard_links`
  - `preserve_security` / `preserve_sacl`
  - `preserve_sparse_files`(サイズが実データと乖離するため)
  - 実際にreparse point/EFS暗号化ファイルが含まれる場合(`preserve_reparse_points`/`preserve_encryption` が true で、かつスキャン中に該当ファイルを検出した場合)
- 件数が少ない場合(初期値: 50ファイル未満)は自動的に `off` 相当の通常コピーにフォールバックする(アーカイブ化のオーバーヘッドが割に合わないため)。
- 進捗report用に `CopyProgress` へ簡易な状態表現を追加する(既存フィールドの `current_path` を「アーカイブ作成中」「転送中」「展開中」のラベルとして流用するか、新フィールド `phase` を追加するかは実装時に決定)。

### UI (`templates/index.html`) の変更

- 既存の `layout`/`policy` の `<div class="field">` と同じパターンで、`archiveMode` の `<select>` を追加(`既定` / `アーカイブのまま転送` / `転送後に展開`)。
- `defaults` オブジェクトと `savePrefs`/`send('startCopy', ...)` に `archiveMode` を追加(既存の [index.html:100](../templates/index.html#L100), [index.html:156](../templates/index.html#L156), [index.html:158](../templates/index.html#L158) と同じ配線パターン)。
- 属性保持オプション(hard link等)と併用不可の場合はエラーメッセージを表示する(新規i18nキー追加)。

### `webview_main.cpp` / `main_cli.cpp` の変更

- `run_copy` 相当の関数([webview_main.cpp:580-599](../core/native/src/webview_main.cpp#L580-L599))に `archiveMode` 文字列パラメータを追加し、`ArchiveTransferMode` に変換して `CopyOptions` にセットする(既存の `policy`/`layout` 変換と同じパターン、[webview_main.cpp:582-588](../core/native/src/webview_main.cpp#L582-L588))。
- `main_cli.cpp` に対応するCLIフラグ(例: `--archive=off|only|extract`)を追加。

- `qfc_core` ターゲットのソースに `src/archive_relay.cpp` を追加。
- 新規リンクは不要(7z.exeは外部プロセス起動のみで、ライブラリリンク不要)。

### 変更しないもの

- 既存のUI項目(layout/policy/mode)のデフォルト値・挙動は変更しない。

## 検証方法

1. `build_native.py` でビルドが通ることを確認する。
2. 7-Zip未インストール環境で `archiveMode` を選んだ場合、明確なエラー表示になり、既定コピーにフォールバックしないこと(黙って壊れた結果を返さない)を確認する。
3. 小ファイル大量(例: 1KB×5,000個)を用意し、以下を**実測**して数値を記録する(結果は捏造せず、速くならなかった場合はその通り書く):
   - a. 通常コピー(ローカルドライブ間)
   - b. アーカイブのまま転送(ローカルドライブ間)
   - c. 転送後に展開(ローカルドライブ間)
   - d. 上記a〜cをUNC/ネットワーク共有宛先でも実施し、「展開ありモードがネットワーク宛先で本当に速くならない」という仮説を実測で検証する
4. `preserve_hard_links`等との併用時に、意図通りエラーで停止することを確認する。
5. アーカイブ作成中・転送中・展開中それぞれの段階でキャンセルし、一時ファイル(`%TEMP%`のアーカイブ、宛先の一時アーカイブ)が残らないことを確認する。
6. CLIから `--archive` フラグでの実行を確認する。

## リスク

- **効果が期待外れになるリスク(高)**: 上記の技術的制約により、「転送後に展開」モードはネットワーク宛先では速くならない、またはむしろ遅くなる可能性がある。検証結果次第でUI上の推奨導線(既定でどのモードを勧めるか)を変更する必要がある。
- **7-Zip依存**: 7-Zip未インストール環境では機能しない。バージョン差異(7z.exeの引数互換性)もQuick7Zip側の `IsSupportedSevenZipVersion`([engine.cpp:216-223](file:///C:/Users/0120025-Z100/source/project/Quick7Zip/core/native/engine.cpp#L216-L223))と同様のチェックを移植する必要がある。
- **属性欠落リスク**: hard link/ACL/reparse point/EFS/sparse fileはアーカイブ経由で失われる。併用禁止ガードの実装漏れがあると、ユーザーが気づかないままこれらの属性が失われた状態でコピーが「成功」と表示される重大なリスクになる。ガード条件の網羅性を実装時に再確認する必要がある。
- **一時ディスク容量**: ソース側・宛先側の両方に、アーカイブ分の一時ディスク容量(元データとほぼ同サイズ)が一時的に必要になる。
- **セキュリティ**: 外部プロセス(`7z.exe`)を `CreateProcessW` で起動するため、パス・引数のクォーティングに不備があるとコマンドインジェクションの余地が生まれる。Quick7Zipの `QuoteWindowsArgument` ヘルパーをそのまま移植して使う。
